## 1. 何を作るか（最小）

**新規ボードを縦向きにできる。** 見た目は現行サッカーピッチを 90°した世界（ゴール上下）。駒は最初からその座標で置く。

| 必須 | 内容 |
|------|------|
| データ | `BoardDocument` に向き（例: `pitchOrientation: "landscape" \| "portrait"`）。既定 **landscape**。既存セーブは landscape |
| 描画 | 縦ではゴール↔ゴール＝画面上下。レーンはゴール方向。CSS で枠だけ縦にして横ピッチを入れるのは **不合格** |
| ツール | 既存の駒・Pen・Run / Dribble / Pass / Link。新ツールを足さない |
| 番号 | 画面正立（駒ラベルをピッチと一緒に寝かせない） |
| 帯 | 縦ボードでは試合帯を **出さない**。縦用帯を設計しない |
| ハーフ | サッカー縦のフル↔ハーフ（＋既存 `pitchFlipped` 相当）。フルだけのスパイクで止めてユーザに確認してよい。勝手にスキップして「後で」にしないなら、フル合格後に続けてハーフまでやれ |
| UI | 新規時 or 試合タブで向きを選ぶ。**既存横ボードをワンクリックで縦に変換するボタンは禁止** |
| i18n | Short キー。`ja`+`en`。ドロワーを広げない |

**合格の見た目:** 現行 ZB ピッチキャプチャをペイントで 90°し、駒を置いたもの。それ以上のデザイン発明は不要。

## 3. ガードレール（Cursor Auto がやりがちな悪癖）

仕様を満たすためでも、次をやったら **やりなおし。**

### スコープ

1. **頼まれていないファイルを「ついでに」直さない。** リネーム・分割・描画エンジンの抽象化・「後で楽になる」リファクタ禁止。
2. **docs を増やさない。** 正本は既にある。`VERTICAL_PITCH.md` の Phase 表を勝手に書き換えない。実装でフィールド名が決まったら、ユーザが頼むまで docs は触らない（または `types` のコメント1行まで）。
3. **未追跡の別作業 docs を commit 対象にしない**（ユーザがコミットを頼んだときも、この機能のファイルだけ）。
4. **「完成度」で帯・LP・How-to・changelog を足さない。** How-to 1行が必要なら `howTo.ts` の既存セクションに短い1文だけ。新規セクション禁止。
5. **テストや Story を大量に足して範囲を証明しない。** 既存パターンに乗る最小テスト（`aspectFor` 縦比、persist 既定 landscape）があれば十分。

### 描画・座標（いちばん多い失敗）

6. **キャンバス全体 / ボード全体に `transform: rotate(90deg)` や `ctx.rotate(π/2)` をかけて終わり、にしない。** 番号・ツールヒット・Export が壊れる。ラベルはスクリーン正立のまま、ピッチ図法だけゴール上下。
7. **`aspectFor` だけ逆数にして `drawPitch` を横のまま、にしない。** 不合格（縦の箱に横ピッチ）。
8. **landscape と portrait で駒座標の意味を共有し、切替時に変換しない。** 向きはボード生成時に固定。persist で欠けるキーは `landscape`。
9. **ハーフを「横ハーフを CSS で切る」で済ませない。** 縦世界の長さ半分。

### UI / i18n

10. **ドロワーに長文の横並び行を足さない。** 向きは既存のフル／ハーフと同じクラス（セグメント / `drawer-stack-actions`）。`if (locale === "ja")` 禁止。
11. **Short なしのボタンラベル禁止。** `npm run test:i18n-chrome` を UI 変更後に必ず。
12. **PitchLookPicker の横向きグリフを無理に回して両用アイコンにしない。** 最小なら文字セグメントでよい。

### 品質プロセス

13. **`tsc` / テストを `--no-verify` で逃げるな。** コミットはしないが、自分の変更は `npx tsc --noEmit` と `npm run test:i18n-chrome`（UI を触ったら）を通す。
14. **ブラウザで横ボードの回帰を見ないで終わらせない。** 新規縦だけでなく、既存の横フル・ハーフ・配信モード・帯あり横、を一度は踏む。
15. **秘密・`.env`・本番 URL をファイルに書かない。**
16. **ユーザが頼むまで git commit / push しない。** amend / force 禁止。
17. **別 Agent 用の追加プロンプトや SUMMARY.md をリポジトリに作らない。** 報告はチャットだけでよい。
18. **不明なら勝手に製品判断しない。** 迷ったら縦をサッカー限定・ハーフはフルの次、の小さい方を採り、報告に「判断」と書く。

## 4. 実装の順（この波を守れ）

1波ごとに `npx tsc --noEmit`。描画が見える波ではブラウザ確認。

### 波 1 — データと比

- 型 + persist 既定 `landscape`
- `aspectFor(sport, pitchView, orientation?)`（または同等）。portrait フルサッカーは **68:105**（横の逆）
- 既存呼び出しは orientation 省略時 **今と同一比**（回帰ゼロが目標）

### 波 2 — 描画とヒット

- `drawPitch*` / `drawBoard` / ポインタ→正規化座標が縦で正しい
- レーンがゴール方向
- 駒ドラッグ、線ツールが縦ボードで置ける
- ラベル正立

### 波 3 — UI と帯

- 新規ボードまたは試合タブで portrait を選べる（横→縦変換 UI なし）
- portrait では試合帯を描かない / オンにしても出さない
- i18n `ja`+`en` + `test:i18n-chrome`

### 波 4 — ハーフ

- 縦 + `pitchView: "half"` + `pitchFlipped`
- 局面スイッチで向きが変わらないこと（向きは Board、ハーフは Board 既存どおり）

Export PNG は波 2 の contain が正しければ既存 `exportPng` が追従するはず。壊れたら最小修正。投稿用 9:16 を新発明しない。
