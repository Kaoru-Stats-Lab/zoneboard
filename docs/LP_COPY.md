## 2. なぜこの稿か（判定ルール）

コピーは二本柱にする。

1. **何を見せるか** — 配置と動きを、ピッチの上で。
2. **どう画面に入るか** — 既存の画面構成を保ったまま足す。

置き場を分けた理由は、証拠の種類が違うからである。

| 層 | 書いてよい | まだ書いてはいけない |
|---|---|---|
| H1 | スタメンを置く。パスと動きを見せる | 「OBSの枠はいじらない」 |
| payoff | いつもの画面に、ピッチを足す | シーンを作り直さない、ソースを増やすな |
| キャプション | 顔とチャットは今の場所。ボードは別ウィンドウ | みんなこうしたいと思っている |
| 敵 | 書かない | スライドを捨てる |

**観察された画面行動は書く。配信者の心理と OBS 内部構造は書かない。**

- 「枠を崩したくない」は一次証言がない。意図の断定はしない。
- 視聴者が見ているのは最終映像だけ。シーン切替かソーストグルかは確認できない。
- したがって「OBSの枠はいじらない」「シーンを作り直さない」は H1 に載せない。
- 「いつもの画面に足す」は、画面上のアンカー（顔・チャット・スコア）が動かず図が乗った、という観察の言い換えである。

## 3. 出発点の仮説（リサーチ前）

プロダクト動機（[`PRODUCT_NOTE.md`](PRODUCT_NOTE.md)）は、解説配信で **Google スライドの図形いじり** を見たこと、既存 Web ボードは **配信時にピッチが小さい** こと、VTuber 同時視聴では **アバター・スコア・チャットは OBS 側** という境界だった。

LP 五役合議（2026-08-23）では、現行 LP を Duo Reader 型の読み物と診断した。商品は OBS の中の芝生なので、ヒーローはキックオフ前の仕事に揃える。狭い本文と CTA 一つは残す。

そこから先に、コピー用の仮説が並んだ。

## 4. 実施したリサーチ

順に行い、後段が前段の主張を上書きしている。

### 4-1. プロダクト事実（内部）

ZoneBoard は登録なし、ブラウザ、localStorage、最大 3 枚。配信モード（`B`）で chrome を消す。OBS への正規経路は **ウィンドウキャプチャ**（ブラウザソースは localStorage を共有しない）。製品はボードであり、録画ソフトではない。

この層だけは仮説ではない。lede の手順と「出す」の配信モードは、ここに根拠がある。

### 4-2. 市場・競合（SPEC / 既存調査）

日本語圏には専用 Web ボードがある（TACTICALista 等）。「全画面がない市場」は誤り。差は配信契約（chrome を消す）とブランディング主権。LP の敵を「専用ボードが無い」にはできない。

### 4-3. コピー案と第二意見（ChatGPT / Claude）

案 A〜E を出し、外部に「証拠の射程」を聞いた。一致した制約:

- CTA は「ボードを開く」のまま。
- コーチ FA/US 記法を H1 に載せない。
- 未検証の「30 秒」を見出しにしない。
- **Google Slides を主敵として証明する一次データが無い。**
- **「OBS の枠をいじりたくない」の本人発言が見つからない。**

この時点の判定は厳しかった。「配信の枠はそのまま」は証拠不足として H1 から外す、が暫定結論だった。

### 4-4. Deep Research 1 — ツールと発言

公開の解説・同時視聴から、専用戦術ボード（JLA、TACTICALista、CocoBoard 等）の使用は観察できた。配置・パス・ランをピッチで見せる、は強い。

見つからなかったもの:

- スライドを主道具とする、という一般化
- 「枠を崩したくない」という一人称
- 視聴者が「ピッチ最大化が最優先」と語っていること

### 4-5. Deep Research 2 — 画面構成のコーディング

対象はサッカー同時視聴・解説の「戦術の瞬間」。最終配信映像だけを見て、レイアウトが跳んだか否かを代理指標で分類した。

**標本:** 10 配信（日本語 5 / 英語 5）、戦術局面 14。YouTube アーカイブ偏重。Twitch は保存が短く収集しにくい。大規模チャンネルが検索上位に出やすい。戦術可視化が 30 秒未満のクリップは除外。

**ラベル（視聴者画面上の代理指標）:**

| 型 | 意味 |
|---|---|
| A | レイアウト切替（顔カメラ位置・外枠デザインが跳ぶ） |
| B | 同一レイアウト内に図を重畳（アンカー不変、ソース追加の見た目） |
| C | 全面置換（試合映像や出演枠が消え、図が全画面） |
| D | 図なし・口頭のみ |
| E | 判定不能 |

**局面単位 (n=14):** A 1 / B 6 / C 2 / D 5 / E 0。  
視覚図解あり (A+B+C=9) のうち B は **66.7% (6/9)**。A は 11.1% (1/9)。

**チャンネル単位の主たる型 (n=10):** B 5 / D 3 / A 1 / C 1。  
図解を使う 7 チャンネルに限ると B は **71.4% (5/7)**。

日本語 5 本のうち B が 4。英語は A/B/C/D に分散。n=10 では言語差を結論にしない。

## 5. 仮説の帰結

| 仮説 | 帰結 | コピーへの反映 |
|---|---|---|
| H-job 配置と動き | **支持。** ボード・手書き・スライド・実物マグネットまで、図解の中身は配置・パス・ラン・ビルドアップ・プレス | H1 を「スタメン」と「パスと動き」に分ける。「形」だけでは狭い |
| H-layout 画面は維持され図が足される | **画面行動としては支持（代理指標）。** 図解局面の 66.7%、図解チャンネルの 71.4% が B | payoff「いつもの画面に、ピッチを足す」。H1 には上げない |
| H-layout の心理版「枠を崩したくない」 | **未証明のまま** | 使わない |
| H-layout の内部版「OBS の枠はいじらない」 | **観察不能** | 使わない |
| H-capture ウィンドウキャプチャ | **製品事実。** 観察上の B を再現する手段の一つ（既存シーンにソースを足す） | lede。OBS 固有名詞は必須にしない（配信ソフト） |
| H-rival スライドが主敵 / スライドが枠を崩す | **反証寄り。** 専用ボードが既にある。M08・M12 はスライドでも B | 「スライドを捨てる」不採用。対比に使わない |
| H-pitch ピッチ最大化が視聴者最優先 | **未証明。** C 型（全面置換）も存在する | H1 に「主役にする」を置かない |
| H-face 顔とチャットは普遍 | **弱い一般化。** 顔出ししない人、チャット非表示、VTuber がいる | キャプションの状態記述に留め、H1 に上げない |
| H-30s | **未計測** | 数字を書かない。「キックオフ前」は場面として残す |

ChatGPT は画面コーディング後、「枠はいじらないを H1 から完全除外」を撤回した。ただし撤回したのは **画面構成の観察** であり、OBS 運用の代弁ではない。Claude は H1 を仕事のまま据え置き、キャプションの状態記述を観察に格上げした。両者の交差が本決定稿である。

**H1 = 仕事。payoff = 観察された足し方。lede = 製品手順。キャプション = 状態。クレド = 小さく作る理由。**

## 6. 意図的に捨てた文言

| 捨てた文 | 理由 |

| OBSの枠はいじらない | OBS 内部を断定する |

## 7. 限界（コピーを止めないが、誇張は止める）

- n=10 配信、14 局面。統計的一般化はしない。
- YouTube・中〜大規模偏重。同接数十人は過小代表。
- 代理指標。OBS プロジェクトは未確認。
- 言語差は言わない。
- これ以上の Deep Research はコピーロックをブロックしない。タイムスタンプ監査は任意。

出荷後に崩してよい条件の例: 配信者インタビューで「枠を崩したくない」が一次で出る、OBS 内部が B と矛盾する、小規模標本で C/A が多数派になる。そのときは payoff を先に見直す。H1 の仕事（置く / 見せる）は製品そのものなので、観察の揺れでは動かさない。
