## 2. 機能要件

### A. 局面名の可読性（P0）

現状: `1 · Pressing` がチップに詰まり、長いラベルで横溢れしやすい。

最低限:

- 番号とラベルの **視覚階層**を分ける（番号は常に見える・ラベルは truncate + `title` に全文）
- アクティブ局面は既存 `active` を維持しつつ、ラベルが読めるコントラスト
- ラベル未設定時は番号のみ（または既存プレースホルダ運用を壊さない）
- **局面ラベル入力欄**（Drawer 内の既存フィールド）があれば、フォント／余白／hint を整え「名前がチップに効く」と分かるようにする
- 横スクロールを新設しない。`.scene-chips` は折り返し or 縦スタックで Drawer 幅内に収める（i18n ガードレール）

推奨レイアウト（一例・DOM は任せる）:

```
[ #1 ]  Pressing high          ← 1行・label truncate
[ #2 ]  Build-up left
```

チップを完全に捨てて巨大カードにするのは **禁止**。

### B. 極小プレビュー（P0 · パフォーマンス注意）

各局面チップ（または行）に **極小**のピッチサムネを付けてよい。

制約:

| 項目 | 目安 |
|------|------|
| サイズ | おおよそ **36–48px 幅**（Drawer を食わない） |
| 内容 | 芝＋ピッチ線＋駒・ボールの簡易シルエットで十分 |
| 更新 | 局面切替・駒配置変更のあと。毎フレーム再描画しない |
| 失敗 | 生成失敗時はプレビューなしでテキストのみ（UI 崩壊禁止） |
| 配信モード B | Drawer 非表示のため問題なし。放送中に裏で重く回し続けない |

実装ヒント:

- offscreen canvas / 既存 `drawBoard` の縮小描画を **キャッシュ**（`scene.id` + 軽い revision）
- 全局面をフル解像度 PNG で持たない
- The Tactics App のような大きなカードサムネにしない

### C. 選ばせるときだけ大きめプレビュー（P0）

`BoardLimitDialog` を拡張するか、同型のダイアログで:

- **ボード上限の差し替え**（既存）に、各ボードの **中プレビュー**（例: 120–160px 幅）を足す
- 文言・キャンセル／選ぶ操作は既存キーを流用（`boardLimitPick` 等）

任意だが推奨:

- 局面が上限で「どれを消す／どれを開く」ような **選ばせる**フローが既にあれば、そこにも同サイズのプレビュー
- 日常のチップ切替をダイアログ化しない
