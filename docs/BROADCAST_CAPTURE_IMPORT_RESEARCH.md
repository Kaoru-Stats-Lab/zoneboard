## エグゼクティブサマリ

**推奨: Go（Later 大型 · Phase 付き）。** サッカー本線は **ライブ即時配置ではなく、シーク複数キャプチャ → HT で自動配置＋修正＋解説**。コマ抜き需要は大きい。Homography 必須。一時停止 UI が検出を汚すのは **Phase 1/2 既知リスク**。帯 B（16GB）でも HT 作業なら余裕が増える。

## 1. 誰のどんな場面か

| ペルソナ | 場面 | Must? | 現状の回避策 |
|----------|------|-------|----------------|
| **Watchalong（本線）** | **シークで複数枚キャプチャ → HT / 停止区間で配置・解説** | **最高** | 手置き · 口頭 · スクショをそのまま見せる |
| **事前収録 · VOD 解説** | 録画を止めて局面化 | **高** | 同上 |
| **ライブ中の即時取込** | プレー進行中に取込→配置→解説 | **低〜中** | ロースコアでもボールが動き続け、解説中にシーンが変わる → **本線にしない** |
| **X 分析 · ライター** | スクショから図解 | **中** | 手置き |
| **コーチ教材** | ドリル図 | **低〜中** | 手置き |

### 1b サッカーの本線フロー（2026-08-30 追記）

ロースコア · 連続プレーでは「ライブ中に何度もキャプチャしてすぐ配置解説」は稀、という仮説を **採用**。

```text
DAZN / スポーツTV / Abema / 地域リーグ動画
  → シークバーで「あの瞬間」へ
  → フレーム複数枚を抜く（コマ抜き需要はここで大きい）
  → ZB に取込 → 自動配置 + 手修正
  → ハーフタイム（または配信の解説ブロック）で局面をめくって解説
```

| 含意 | 内容 |
|------|------|
| **コマ抜きエンジン** | ライブ `Ctrl+V` より、**VOD/配信プレイヤー上のシーク抽出**の価値が高い |
| **複数局面** | 1試合で数枚ストック → Scenes との相性が良い（取込 = 新局面ドラフト） |
| **配信非干渉** | HT 中・準備中の抽出が主なら、帯 B でも余裕が増える。ライブ中抽出は副 |
| **一時停止 UI** | ポーズすると **中央の一時停止アイコン · コントロールバー**が映り、検出精度が落ちる。地域リーグ動画も同様 |

**Phase 1/2 既知リスク — プレイヤーオーバーレイ:**

| 汚れ | 対策の方向（初期） |
|------|-------------------|
| 一時停止アイコン（中央） | ポーズせず近傍フレームを抜く · 中央マスク · ROI クロップ |
| シークバー / ロゴ / スコアバグ | ピッチ 4 点内だけ検出 · 下敷き Phase 1 では目視回避 |
| 放送テロップ | 手でゴースト削除。局別 ML 除去は初期やらない |

### 入力メディアの実態

| 優先 | 入力 | 備考 |
|------|------|------|
| **①** | **動画シーク → 1フレーム**（MP4 · ブラウザ録画 · プレイヤー） | 本線フロー。コマ抜き需要大 |
| **②** | クリップボード貼付（`Ctrl+V`） | スクショ。ポーズ UI が焼き込まれやすい |

**実写の特徴:** 主入力は **TV 斜め俯瞰**。パースあり → Homography 必須。

## 2. スコープ境界

### 2a Phase A / B（再定義）

調査により、当初の「Phase A=静止画 / Phase B=動画フレーム」を **出荷機能の段階**に再定義する。

| Phase | 内容 | 役割 |
|-------|------|------|
| **1（直近）** | **トレーシング・ペーパー + 手動4点 Homography** | ユーザがピッチ特徴点をポチる。**自動4点は狙わない**（画質・アングル依存）。下敷きガイドで手置き加速 |
| **2（大型の芯）** | **クライアント自動駒ドラフト** | 手動4点のあとに検出。ゴースト微調整。**100% 再現は成功条件にしない** |
| **3（将来・研究）** | **ピッチ線の完全自動キャリブ** | 画質が良いときだけ。失敗時は手動4点にフォールバック |

### 2a-1 精度と画質（2026-08-30 追記）

**「すべての入力で 100%」は言わない。きれいな入力では 100% に近づけたい、が本音。**

| 階梯 | 入力の例 | 期待 |
|------|----------|------|
| **ゴールド** | DAZN 等高ビットレート · ピッチ線がはっきり · ポーズ UI なし（または近傍フレーム） | 手動4点のあと、自動駒が **ほぼ実配置どおり**。手直しは 0〜数個。**ここは妥協しない** |
| **シルバー** | 一般スクショ · やや圧縮 · 軽いテロップ | たたき台として十分。数秒のドラッグ修正 |
| **ブロンズ** | 低画質 · 線が読めない · ポーズアイコン中央 | 自動駒は期待しない。下敷き＋手置き、または取込中止 |

| 要因 | 影響 |
|------|------|
| **画質** | 低ビットレートではペナ角が見えない → 自動不可。**高画質なら手動4点が正確に取れ、射影も安定** |
| **アングル** | 毎回違うのでキャリブは手動4点のまま（ゴールドでも） |
| **遮蔽 · UI** | 高画質でもポーズすると落ちる → フレーム戦略がゴールド達成の前提 |
| **成功の定義（出荷）** | シルバー以上で「たたき台＋短時間の手直し」。**KPI（本音・ゴールド）:** DAZN 級で手直しほぼ不要 |
| **成功の定義（ジョブ）** | **駒が多いほど「だいたい置き」の価値が跳ねる。** ペナ前 12–18 人を手置きする苦痛の削減が本線。70% 検出でも勝ち。欠落・誤検出はピック／ドラッグで埋める |
| **マルチフレーム** | 同局面を数枚取れるとゴールドが生きる（下記 2a-2） |

**キャリブの本線は手動4点のまま。** ゴールドで精度を出すのは主に **検出・射影・オーバーレイ回避・複数フレーム**側。自動4点当ては Phase 3。

### 2a-2 同局面・複数フレーム（ゴールド向け · 2026-08-30）

DAZN 級なら、**1枚より同局面の複数枚**のほうが駒配置がきれいに出やすい、という仮説を採用する。

| 使い方 | 効果 |
|--------|------|
| **最良フレーム選定** | 遮蔽が少ない・足が芝に付いている・ポーズ UI がない1枚を選ぶ |
| **近傍フレーム（非ポーズ）** | 一時停止アイコンを避けつつ、ほぼ同じ配置を残す |
| **足元の安定化** | 数フレームで検出した足元を突き合わせ、外れ値を落とす（平均・中央値など） |
| **欠落補完** | A 枚で欠けた選手を B 枚の検出で補う（同一 Homography 前提） |

| 設計メモ | 内容 |
|----------|------|
| **キャリブ** | 手動4点は **代表1枚（または共通）で1回**。枚ごとに打ち直さない |
| **入力 UX** | コマ抜きで「この付近を数枚ストック」→ 取込がまとめて食べる、が自然 |
| **必須か** | 1枚でも動く（シルバー）。**ゴールドの本音精度は複数枚ありき**に寄せる |
| **負荷** | 帯 B ではプロキシ解像度のまま数枚まで。枚数上限を設ける |

### 2f 4:3 → 16:9 の引き伸ばし（2026-08-30）

2010年代前後の **4:3 放送を、現行プレイヤーが 16:9 に横引き伸ばし**した映像（アーカイブ YouTube 等）は、選手・ピッチ線が横に潰れる。

| 判定 | 内容 |
|------|------|
| **ゴールド** | 正しいアスペクト（現行 16:9、または 4:3 を黒帯付きで維持） |
| **今はやらない** | 引き伸ばし映像での「DAZN 級精度」。Homography が FIFA 実寸と一致しない |
| **Later** | ユーザ指定の **4:3 補正（アンストレッチ）** — アーカイブ需要で要る可能性が高い |
| **コピー** | デフォルトで長文注記は出さない。失敗時ヒント程度 |

| 世代 | 傾向 | キャリブ |
|------|------|----------|

### 2h 縦ピッチ（Later · **やる** · 2026-08-30 · 方針更新）

**仕様の正本:** [`VERTICAL_PITCH.md`](VERTICAL_PITCH.md)。

**どこかのタイミングで実装する（B-072）。** ゴール↔ゴールを上下にした **縦ピッチ用データ／モード**を持つ。スマホ／SNS・紙の戦術書・縦配信の前例に合わせる。

**採る（2026-08-30 更新）:** 縦は **別データ（別ボード／別シーン向き）**。横で置いた局面を縦に **切替しない**。座標の写像は不要。やるのは **レイアウト調整**（アスペクト・UI・OBS 枠・PNG 既定）だけ。

**やらない:**

| やらない | 理由 |
|----------|------|
| 横↔縦の同一局面切替（座標持ち越し） | 難易度がレイアウト以上になる · 必要性が薄い |

**根拠:** 紙の戦術書の縦図 · 縦ピッチで配信している配信者 · スマホ／SNS

詳細（フル／ハーフ、帯なし、受け入れ絵、OBS）は正本に集約。

## 3. 動画前段（コマ抜き）

### 3a video-frame の能力と限界（前提）

[sugudasu.com/video-frame](https://sugudasu.com/video-frame): ブラウザ内 MP4/WebM · シーク · PNG · サーバ非送信 · GIF/編集なし。大容量・形式非対応・フレーム誤差あり。

**エンジンは使える。** ブランドは出さない。

### 3b 置き方の比較

| 案 | 構造 | 判定 |
|----|------|------|
| **L. 外部リンク** | sugudasu 等で PNG → ZB import | **非推奨** — 離脱 · UX 分断 · 他ブランド |
| **E. 他ドメイン iframe** | 外部画面埋め込み | **非推奨** — サードパーティ感 |
| **P0. ボード同一バンドルにベタ載せ** | 戦術ボード JS に抽出を混在 | **可だが必須ではない** — 配信タブと CPU/メモリ競合しやすい |
| **P1. 表 ZB · エンジン分離（決定）** | 共有クライアントモジュール、または同一ドメイン別面（例 `/tools/frame`）。処理はブラウザ内 | **推奨** — 管理・更新をボードと分離。ブランドは ZB |

### 3c 推奨の置き方（決定 · 2026-08-30 追記）

**表は ZoneBoard。コマ抜きエンジンはボード本体と分ける。処理はローカル・ブラウザメモリ。**

- [video-frame](https://sugudasu.com/video-frame) 相当のロジックは流用可。**SUGUDASU 名は出さない。**
- 「ZB に移植」＝ sugudasu.com に飛ばさない、という意味。**モノリス必須ではない。**
- 管理がスムーズなら **モジュール分離 or 同一ドメイン別面**で決定してよい。

### 3d 守る境界（ハード · 配信）

**動画から画像を抜いている最中でも、OBS がキャプチャしているボード配信が途切れない／カクつかない。**

| 守る | 意味 |
|------|------|
| **ローカル** | 動画バイナリをサーバに上げない（デフォルト） |
| **メモリ内** | 端末ブラウザ内で完結。巨大デコードは制限・警告 |
| **配信非干渉** | ボードの rAF / キャンバス描画を長時間ブロックしない。必要なら Worker · 別タブ／別面 · アイドル時のみデコード |

**この境界を守れないときだけ** エスカレーション:

1. **同一ドメイン別面 / 別タブ**で抽出を隔離（ボード配信タブとプロセスを分ける）  
2. **別ドメイン**（運用・隔離のため。ブランドは ZB 側に寄せる）  
3. **サーバ処理** — 最終手段。非送信楔と衝突するため、採用するなら明示 opt-in と「配信中は使うな」を前提にする  

本線の成功条件は **1 に落ちる前に、共有エンジン + 配信タブ非干渉で足りること。**

### 3e 想定 PC 構成（2026-08-30 改訂）

正本: [`STREAMER_RIG_RESEARCH.md`](STREAMER_RIG_RESEARCH.md)。**旧ラベル（A=16GB下限）は廃止。**

スポーツ watchalong はゲーム実況と違い **RAM（タブ多重 + OBS）がボトルネック**。GPU 余力はあることが多い。設計標的は **帯 B**。

#### 机の形（主想定 · サッカー解説）

| 項目 | 想定（主） | 備考 |
|------|------------|------|
| **台数** | **Single PC が大半**（推定 90%+ · proxy） | Dual は少数。二台同期は本線にしない |
| **モニター** | **2画面が標準** | 映像/ZB · OBS/Chat/Stat。3画面は帯 A |
| **OBS** | 窓キャプチャで ZB（配信モード B） | [`OBS.md`](OBS.md) |
| **同時負荷** | 試合映像デコード + ブラウザ多重 + OBS + ZB | 3D ゲーム描画は主因ではない |

#### スペック帯（決定）

| 帯 | 層 | 目安 | 局面取込 |
|----|-----|------|----------|
| **A · Pro** | 専業 · 大手 | 32–64GB · 3070/4070 級+ · 3画面 | 高速抽出でも配信影響を最小化できる目標 |
| **B · Standard（下限標的）** | 一般スポーツ配信 | **16GB · Single · i5/R5 · 1660/3060 級 · 2×1080p** | **4ルール必須**。空き RAM 僅少。OBS 落ちリスク |
| **C · Budget** | ライト · 1画面 | **8GB** · iGPU / 薄型ノート | **自動 AI 制限**。Phase 1（4点・下敷き）中心 |

#### 帯 B 向け 4 ルール（配信中）

1. Homography / 画素解析は **Web Worker**（メインスレッド非凍結）  
2. 入力は **640² または 720p プロキシ**に落としてから計算  
3. 一時画像は即破棄。永続は座標 JSON。大きな画像を IDB に残さない  
4. 押下直後は解析中表示 → 数秒後ゴースト（トーク継続可）

#### 構成 × 境界

| 状況 | 推奨 |
|------|------|
| **帯 B · 2画面 · 配信中** | ボード窓（OBS 掴み）と抽出を **Worker + プロキシ**で同一機。落ちるなら **別タブ** |
| **帯 C · 1画面 · 配信中** | 自動抽出 OFF。スクショ + 手動4点。または配信前 |
| **帯 A** | 余裕。それでも 4K 生フレーム直投入はしない |

#### UAT

- [ ] **帯 B（16GB）** 相当で、OBS 窓キャプチャ中にプロキシ抽出してもキャプチャが数秒固まる／落ちない  
- [ ] 帯 C では自動抽出がデフォルトで走らない（または強い警告）  
- [ ] メインスレッドが Homography でブロックされない（Worker）  
- [ ] Phase 2 ONNX は帯 B 配信中 **デフォルト慎重**（OFF またはプロキシ後のみ）

## 4. PNG → scene

### 4a 変換プロセス（3ステップ）

1. **ピッチアライメント（手動4点）** — 実写上の特徴点を **ユーザが指定** → Homography \(H\)。自動当てに依存しない  
2. **プレイヤー検出（Phase 2）** — 軽量 ONNX または HSL 等で足元候補（画質次第で欠ける）  
3. **射影** — \(H\) で 2D 座標 → ゴースト駒  

画質が悪く4点が目視できない場合: 取込を諦めるか、下敷きなしの手置きにフォールバック（無理に自動しない）。

参考: [Roboflow — camera calibration sports](https://blog.roboflow.com/camera-calibration-sports-computer-vision/) · [StatsBomb — map homography](https://blogarchive.statsbomb.com/articles/football/creating-better-data-how-to-map-homography/) · [arXiv:2207.11709](https://arxiv.org/abs/2207.11709)

### 4b 自動 vs 手修正（Draft & Snap）

| 層 | 方針 |
|----|------|
| **自動** | 足元候補 → **半透明ゴースト駒**（チーム色は色抽出できれば仮分け） |
| **手** | ドラッグ微調整 · 欠落追加 · 誤検出削除 · **確定** |
| **出さない（初期）** | 背番号 OCR · 線種自動 · 個人同定 |

精度期待: **70–80%**（遮蔽 · カメラ外 · 影）。100% を求めない。  
目標 UX: ゼロから 15–30秒 → **自動 + 微調整 3–5秒**。

### 4c 失敗時 UX

- プレビュー（ゴースト）→ 確定 / 破棄  
- 部分取込可（検出ゼロでも Phase 1 下敷きだけで価値あり）  
- **既存 scene の無断上書き禁止** — 新規局面 or 明示マージ

### 4d 身元ピック（Phase 2 付帯 · 2026-08-30）

**画像からは「誰か」は分からない、を前提にする。** 背番号 OCR・顔・外部 DB 同定は本線にしない。

配置（ゴースト）のあと、配信者／解説者が **既知のスカッドから即ピック**する。

| 条件 | 内容 |
|------|------|
| **前提** | 今夜の名簿に **ベンチ入り（マッチデイ・スカッド）** が入っている |
| **候補 A** | スカッド全体（ホーム/アウェイ別） |
| **候補 B** | **そのタイミングでピッチにいたメンバー** — ユーザが絞る、または「未アサインのピッチ側セット」 |
| **操作** | ゴースト選択 → 候補から1人（番号チップ / 短いリスト）。連続で次のゴーストへ |
| **人の強み** | 贔屓・熟知チームの配信者は **立ち姿・背格好**で瞬時に誰か分かる。OCR より **ピック UI の速さ**がボトルネック |
| **結果** | 駒に `number` · `label` を載せる。色はチーム側 |
| **楔との関係** | 背番号ファースト（[`PRODUCT_NOTE.md`](PRODUCT_NOTE.md)）。選手 DB・スクレイプは引き続きやらない |
| **HT フロー** | シーク複数枚 → 取込 → 配置ドラフト → **誰か当て** → 解説 |

UX 含意: 候補は **顔写真グリッドより番号＋短い名前のチップ**でよい（既に頭の中で姿と番号が結びついている）。未使用選手だけ出す・ホーム/アウェイを分ける・連続ピックでタブを閉じない。

未登録試合・番号不明の地方戦では、ピックせず番号なしゴーストのまま解説するか、手で番号だけ打つ。

## 6. リスク · Go / No-Go

| リスク | 緩和 |
|--------|------|
| ONNX / 検出のバンドル重量 · 低スペック端末 | Phase 1 を先に出荷。Phase 2 は opt-in / Pro 検討可 |
| 4点クリックの学習コスト | ガイド短文 · プリセット角のヒント。ウィザード禁止のまま |
| 「100% 斜め」前提の過信 | 真上図パスを残す |
| 著作権・実写キャプチャ | 機能はローカル処理。宣伝素材での無断二次利用は別問題（Outreach 方針） |
| 配信中テンポ | Phase 1 下敷きだけでも可。重い検出は配信前準備向けに振る判断可 |

**Go 条件（案）:** Phase 1 で「下敷き + 4点」後の手置きが体感で半分以下の時間。Phase 2 で XI の過半が ±妥当距離に乗り、確定までおおよそ数秒。  
**No-Go:** サーバ必須 · 連続トラッキング本線 · 確定前の強制上書き · ブランド他社掲出。

## 7. 推奨決定

| 項目 | 内容 |
|------|------|
| **Verdict** | **Go** — 大型アップデートの目玉として Phase 計画付きで採用 |
| **Phase 1** | 下敷き + **手動4点** Homography（自動キャリブに依存しない · 100%再現しない） |
| **Phase 2** | クライアント自動駒ドラフト（ゴースト + 手修正）。キャリブは手動4点のまま |
| **Phase 3** | 自動ピッチ認識（研究 · 画質良いときのみ） |
| **コマ抜き** | **表 ZB · エンジンはボードと分離**（モジュール／同一ドメイン別面）。ローカル・ブラウザ。リンク／他ドメイン iframe 非推奨 |
| **ハード境界** | 抽出中も **OBS 配信が途切れない**。守れないときだけ別面隔離 →（最終）サーバ |
| **触らない（当面）** | 連続トラッキング · 選手 DB · 線自動 · Piero 席 · SUGUDASU 表出 · ジュニアコートキャリブ（次期まで） · **4:3引き伸ばしの自動補正（Later候補）** · 取込 UI での寸法の大仰な注記 |

## 8. 成功指標 · UAT

- [ ] 動画コマ抜き中も配信タブのボード描画が **目視で途切れない**（ハード境界）
- [ ] `Ctrl+V`（またはドロップ）で取込フローが開き、**サーバへ画像が上がらない**
- [ ] 高密度局面（ペナ前など人数多）で、**だいたいの配置ドラフト**が出て手置きより明らかに速い（欠落は許容）
- [ ] **ゴールド:** DAZN / Abema(DAZN) / SPOTV NOW(YT) / **U-NEXT(YT)** の高画質で、手動4点のあと自動駒が体感ほぼ配置どおり
- [ ] U-NEXT の大型右上宣伝があっても ROI 後に4点・検出が使える
- [ ] **ゴチャつき全画面**（ナビ＋おすすめ＋バナー付き）でも、ROI / 手動枠のあと4点が使え、サイドバーサムネを選手と誤らない
- [ ] 上記ソースで四隅ロゴ・下プレイヤーバーが検出を大きく汚さない（ROI / マスク）
- [ ] **シルバー以下:** たたき台＋短時間の手直しで解説に使える（100% 必須にしない）
- [ ] Phase 2: ゴースト提示 → 微調整 → 確定の流れが使える
- [ ] 確定前に既存局面を黙って上書きしない
- [ ] **身元ピック:** ゴースト選択 → マッチデイ・スカッド（またはピッチメンバー絞り）から即当てできる。OCR・外部 DB に依存しない
- [ ] パス / ランは自動で増えない（手描きのまま）
