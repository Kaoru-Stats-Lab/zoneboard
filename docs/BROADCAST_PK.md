# Broadcast — PK戦（ペナルティシュートアウト）表示研究

**更新:** 2026-08-26  
**前提:** 交代は **枠を知らなくても** Broadcast できる（残数 UI なし）。PK は **その場でキッカーが決まる**。  
**関連:** [`BROADCAST_SUBS.md`](BROADCAST_SUBS.md)

---

## 0. 問題

| 事実 | 製品への意味 |
|---|---|
| キッカー順は直前まで未定（監督・選手の意思） | **5人名簿を先に埋めさせない** |
| サドンデスで何本でも続く | 固定5スロットだけだと足りない |
| Streamer は大会ルールより「いま誰が蹴るか・入ったか」 | 規制エンジンより **結果の記号** |
| ZB は試合 scorebug ではなく戦術ボード | 巨大 PK オーバーレイで芝を食わない |

---

## 1. TV / Online がやっていること

| パターン | 内容 | 出典メモ |
|---|---|---|
| **結果ストリップ** | チームごとに蹴った順のマーク列。**得点=○ / 失敗=✕**（色だけに頼らない） | FIFA WC グラフィック: 色覚対応で circle / X を追加（緑赤だけでは不十分） |
| **番号 or 略称** | マークの横や下に背番号・名前が付くこともあるが、**結果記号が主** | 一般的な CL / 国際試合の下段グラフィック |
| **進行中スロット** | 「次」や現在キックだけ強調 | 配信オーバーレイ製品の shootout strip |
| **ゴールヒート** | どこに蹴ったか | 解説・クイズ向け。ライブ Streamer の一次 UI ではない |

**業界の核:** 順番の「名簿」より、**蹴った結果の ○✕ 列**。キッカー名は付随。

---

## 2. なぜ ○✕ が ZB 向きか

1. **キッカー未定でもスロットだけ先に置ける**（空 → 蹴る直前に番号 → ○/✕）  
2. **色に依存しない**（芝・キット・スタジオ黒でも読める。FIFA と同型）  
3. **サドンデス**は列を足すだけ（枠規制を焼かない）  
4. Streamer の頭の中の問いがそのまま UI: 「入った？外した？」

名前フルプレートや「第3キッカー必須入力」は、配信中の遅延になる。

## 3. ZoneBoard 推奨（CL でも通用する最小）

### L1 — PK ストリップ（Broadcast chrome · 主）

試合帯下 or LiveMatch 付近の **2行**:

```
LIV  ○ ○ ✕ ○  ·
AVL  ○ ✕ ○ ○  ○
```

| スロット状態 | 見せ方 |
|---|---|
| 未キック | 空の丸枠（薄） |
| 成功 | **○**（塗り or 太線） |
| 失敗 | **✕** |
| 任意 | 枠内 or 隣に背番号（その場入力） |

#### 行ラベル（決定）

- **`board.homeTeam` / `board.awayTeam` をそのまま使う**（試合帯と同データ）。空なら `Home` / `Away`
- PK 専用の別名フィールドは作らない
- キット色バーはバナーと同じソースでよい（視線の対応）

#### 先行 / 後攻（考え方）

| 層 | 扱うか | 理由 |
|---|---|---|
| **行の身元**（上=Home / 下=Away） | **固定** | バナー得点と一致。トスで行を入れ替えない |
| **誰が先に蹴るか**（コイン・大会慣習） | **製品は判定しない** | 交代枠と同じ。「Home が先」等の規制エンジンを焼かない |
| **列の意味** | **ラウンド番号**（両チームの第1・第2…） | TV の並列 ○✕ と同型。先に蹴った側が、自分の行の左空きを先に埋めるだけ |

配信中の操作は「いま蹴ったチームの次スロットに ○/✕」で足りる。  
**先行フラグは v1 必須にしない。** 後から「次はどっち」ハイライトが欲しければ、トス後の任意トグル `pkFirst: home|away` を **UX 用だけ**足せばよい（順序バリデーションや自動進行はしない）。

- 既定は両チーム **5** スロット表示、サドンデスで **+1 ずつ**（Streamer がボタンで足す）  
- **先に5人を名簿登録させない**  
- 合計点は ○ の数を数えるだけ（規制計算なし）

### L2 — ピッチ（任意・瞬間）

「いまのキッカー」を見せたいときだけ:

- GK 1 + キッカー 1（番号付き駒）をペナルティスポット付近に置く  
- または既存局面をそのまま使い、ストリップだけ更新  

**必須にしない。** 多くの解説はストリップ＋声で足りる。

### L3 — やらない

| 禁止 | 理由 |
|---|---|
| 大会別「何本先取」エンジン | 枠と同様、知らなくてよい |
| **コイン／慣習から先行を自動判定** | Streamer が知るべきライブ事実。製品が推測しない |
| トス結果で Home/Away 行を入れ替え | バナー身元とズレる |
| 緑=成功 / 赤=失敗のみ | 色覚・芝色と衝突。○✕ を正とする |
| 蹴る場所ヒートマップを Broadcast 常時 | 面積・操作コスト |
| OBS scorebug の完全複製 | 役割分担 |

## 4. 操作フロー（配信中）

1. **PK** トグル → 空スロット2行（ラベル = `homeTeam` / `awayTeam`）  
2. スロットクリック: **未 → ○ → ✕ → 未**（色だけに頼らない）  
3. 選択中スロットに背番号（任意）  
4. サドンデス: **+1本**（両チームに空枠）  
5. **PKを閉じる** / リセット  

先行後攻フラグなし。先に蹴った側の行を先に埋めるだけ。

---

## 5. 交代との対比（方針の一貫）

| | 交代 | PK |
|---|---|---|
| Streamer が知らなくてよいもの | 枠・窓・脳震盪ルール | 先取本数・サドンデス细则・**誰が先に蹴るべきか** |
| 製品が出すもの | OUT/IN/INJ の **状態** | ○✕ の **結果列**（ラベルは既存チーム名） |
| 残数 / 残キック枠 | **作らない** | **作らない**（列を足すだけ） |
