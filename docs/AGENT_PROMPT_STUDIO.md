## やれ（この順。1 波ごとに型チェックとブラウザ確認）

### 波 1 — トークン（見た目の連続）

LP とボードの chrome を同じ部屋にする。

- 地 `#0c0d0e`、字 `#f3f3f1`、パネル面 `#161718` 前後、角 2px、Barlow / Zen Kaku（`index.html` のフォントをボードでも使う）
- トップバー・ドロワー・ツールレール・ボタンを白カードにしない。入力は読めるコントラスト（AA）
- ロックアップは暗地のカラー正（`scheme="color" on="dark"`）。金は第一マーカーと LP CTA 以外で増やさない
- 配信ボタンは金ベタにしない（黒地に細い枠）
- ピッチ・駒・線の色は変えない

### 波 2 — キットは Roster

`Drawer.tsx` のキット色ブロック（Home/Away × フィールド/GK）を Match から Roster へ。Home/Away セグメントの直下、貼り付けの前。

- クラブ名入力は Match のまま
- データモデルは動かさない（`setKitColor` はそのまま）
- サッカー系だけ GK 行。ヒント文は名簿側へ

### 波 3 — 準備 / 実況の面

3タブを常時並べない。

- 既定のパネル本体は **Scenes**（チップが最初に触るもの）
- Roster と Match のフルフォームは「準備」1 コントロールの向こう。開いたとき中は既存タブ（順は Scenes | Roster | Match を崩さない。準備面では Roster / Match を出す）
- 実況面にバナー ON なら、得点・カードの **1 行**（フル Match に潜らせない）
- 配信モードは今どおりドロワー非表示。`[` `]` と端の局面切替は残す

実装の形（トグル名、1ボタンかセグメントか）は STUDIO §4「フェーズで出す」を満たせば任せる。新規タブは増やさない。

### 波 4 — 配信中の得点

バナーが表示されているとき、配信 chrome の端から得点（必要ならカード）を Match タブなしで足せるようにする。ピッチを食わない。フォーカスヒントと衝突させない。

### 検証

- `npx tsc --noEmit`
- ブラウザ（Chrome MCP 可）:
  - LP → ボードを開く（地・字・ロックアップが連続して見える）
  - Roster でキット変更 → 全局面の駒色が変わる。Match にキット UI が残っていない
  - 既定パネルが局面。準備を開いて名簿・試合に届く
  - 配信モード: パネルなし、局面切替、バナー ON なら得点、ピッチが主役
  - 390px と 1440px。コントラスト。フォーカスリング
- 配信切替と駒ドラッグがもたつかない（装飾アニメを足して遅らせない）
