## 0. 動機（提督）

ワールドカップ解説など YouTube で、戦術説明を **Googleスライドの図形いじり**でやっているのを見た。サッカー・バレー・バスケなど **俯瞰して戦術を指示する**用途なら長時間使う。Privnote型（浅いPV）と単位経済が違う。

**参考UI:** TacticsLista 等の既存Web戦術ボード（ピッチ俯瞰・選手円・フォーメーション・描画）。機能の方向性は近いが、**配信時にピッチが小さすぎる**のが不満。運営ロゴ透かしではなく **自分のロゴ**にしたい。

## 1. ジョブ

| 誰 | 今日の痛み |
|----|------------|
| 解説系 YouTuber / アナリスト | スライドでコート比・背番号・矢印が毎回崩れる。配信中は画面共有しっぱなし |
| **VTuber（同時視聴・W杯実況）** | 俯瞰ボードを画面の主役にし、アバター・スコア・チャットは OBS で重ねたい。運営ロゴではなく **自分の色**（ロゴ・チーム色・名前付き駒） |
| 部活・アマ監督 | ホワイトボードか紙。共有は写真か口頭 |
| 多競技 | コートだけ違う。駒・矢印・ゾーン・手順番号の型は同じ。**v1 はサカ/バス/バレに固定**（[`SPORTS_SCOPE.md`](SPORTS_SCOPE.md)） |

### VTuber 同時視聴で「ここまでやりたい」境界

参考: W杯同時視聴配信（俯瞰ボード全面＋アバター隅＋スコア帯＋チャット）。

| ZoneBoard が担う | OBS / 配信ソフトが担う（やらない） |
|------------------|-------------------------------------|
| 全画面に近いピッチ（配信モード） | VTuber アバター・立ち絵 |
| 両チーム色・背番号・名前（任意）の駒 | スコアボード・タイマー・テロップ |
| ユーザロゴ透かし | スーパーチャット・アンケート UI |
| スタメン一括配置・局面・ズーム | チャット欄・同時視聴の映像ソース |
| PNG 書き出し（縦投稿用） | 配信エンコードそのもの |

**独自色の出し方:** ロゴ・チーム色・名前表示・（Later）コート色。アバター埋め込みやスコア機能は持たない。

ジョブは「保存場所」ではなく **空間＋駒＋動きの編集器**。

**学習コスト指針:** 「使いこなしたい人が最小学習コストでいける」を優先する。ホットキー・自由曲線・局面切替・画角ズームは **任意の加速装置**。使えない／使わない人は **駒を動かすだけ**で戦術を表現できる、と割り切る。初心者向けウィザードや機能制限で上級者を遅くしない。

**UI/UX 正本（chrome・設定・パネル）:** [`UI_UX.md`](UI_UX.md) — 配信者（デジタルネイティブ）の慣れ（OBS / Canva / Figma）に寄せる。戦術管理画面にしない。

**フットサル・ビーチ:** ジョブ／ペルソナ／配信境界のリサーチは [`FUTSAL_BEACH_RESEARCH.md`](FUTSAL_BEACH_RESEARCH.md)（サッカーと同粒度。現場 FB 待ち）。

**タッチ:** タブレット・大型タッチパネルを想定。1本指で駒／描画、ピンチズーム、2本指パン。ホットキーは PC 限定。物理マグネットボードと同じ「指で動かす」体験をデジタルで再現する。

**ボールと駒:** マルチ選択は使わない。ボールを駒に重ねて離すと吸着し、その駒を動かすとボールも動く（保持者のイメージ）。ボールだけドラッグすれば解除。

**背番号ファースト:** 高校選手権の地方大会やブラジル州選手権など、別地域の配信者は **名前が分からず背番号だけ分かる** ことが多い。名簿・スタメンは番号必須・名前任意。駒の識別子は背番号。

**利き足（任意）:** VTuber・解説向け。駒に L/R/B を小さく表示（向き基準の足側）。未設定なら非表示。バスケ／バレでは使わなくてよい。

**セッション特性:** 1本の解説・1試合準備で **30分〜数時間**。再訪・テンプレ再利用あり → 広告/Pro の単位経済は Privnote よりマシ。

## 2. UX 正本 — 配信で使える領域を最大化

既存ツールの典型問題:

- ツールバーが縦に2〜3段、画面の **25〜30%** を食う
- ピッチ周囲にデッドスペース
- 配信では **ピッチと駒・矢印だけが大きく見えてほしい**

### 2-1. 必須方針

| 方針 | 内容 |
|------|------|
| **Canvas first** | コート／ピッチがビューポートの大半（目安 **≥80%**） |
| **Chrome 最小化** | 設定・保存・フォーメは折りたたみパネル。配信中は閉じる |
| **配信モード** | ツールバー非表示 or 極小、余白ゼロ、ピッチ最大表示 |
| **ホットキー** | 描画・UNDO・駒はキーボード中心 |
| **余白を殺す** | 装飾ネイビー余白を配信モードでは出さない |

### 2-2. 配信モードで残してよい最小UI

- 現在ツールの小さなインジケータ
- UNDO（または Ctrl+Z のみ）
- 「配信モード解除」だけ端に小さく
- **ユーザー設定のロゴ透かし**（§2-4）— ツールバーを隠しても残す

保存・Export・フォーメ・透かし設定は配信モード外 or Esc で閉じるオーバーレイ。

### 2-3. 書き出し

- 透過 PNG（ロゴ透かし焼き込み ON/OFF）
- 手順コマ連番は v1.1

### 2-4. ロゴ透かし（YouTuber カスタム）

| 項目 | 方針 |
|------|------|
| **入力** | ローカル画像（PNG・透過可）。コア方針なら非送信 |
| **表示** | 半透明。四隅プリセット。サイズ・不透明度調整。**贔屓クラブ／協会ロゴはここに置く（芝の上）** |
| **配信モード** | 透かしは常時表示 |
| **タイトル帯** | 試合名バナーは透かしと別・テキスト編集可。スコアは得点から。**国・クラブの紋章は帯に入れない**（SEA 実況のスコアバグ型は真似しない） |
| **やらない** | 運営強制ウォーターマーク。Webcam をボードに埋め込まない（OBS側）。スコア帯へのクレスト埋め込み |

## 3. 最小機能（v1 仮説）

1. 競技プリセット（サッカー / バスケ / バレー、寸法比正しい）
2. 駒（背番号・名前・色・フォーメプリセット）
3. 描画（矢印・線・ゾーン・フリーハンド・テキスト）
   - ゾーン＝空き（◯）。**ブロックを敷くは Pen**（横線2本／囲む）。ブロック専用ツールは持たない
   - Pen は解説インク。液タブ級の筆は追わない。滑らかさは合算点＋ベジェまで（B-047）
4. 試合タイトル帯
5. ロゴ透かし（v1 必須）
6. ローカル保存（JSON / localStorage）
7. 配信モード（v1 必須）
8. 手順再生は v1.1

**やらない（v1）:** 選手DB、**予想スタメン専用機能**（名簿＋配置で足りる。独自色はロゴ・解説側）、動画解析、スクレイピング、SNS投稿、重いアニメ、ボード内Webcam、運営ロゴ強制。**サカ/バス/バレ以外の競技**（ラグビー・アメフト・野球・eSports 等は Later）。**運営カタログのフォーメプリセット**（4-4-2 等を商品として並べない。下記決定ログ）。**視野角の扇形**（概念は知っている。出さない。下記決定ログ）。

### 決定ログ — 駒の向きと視野角扇（2026-08-25）

**視線・視界・体の向きは Football で大事。ZB は体の向き（`facing`）一本で足りるとし、視野角の扇形は出さない。**

知らないから載せないのではなく、戦術語として認識したうえで **敢えて出さない**。体向きと視線を別属性にすると学習コストが跳ね、扇は配信映えと誤読のリスクが高い。口頭解説・線・ゾーンで足りる。

- **持つ:** `facing`（三角ドラッグ・`R`・移動追従）。利き足 L/R もこの向き基準
- **出さない:** 視野角扇、視線と体向きの二属性、駒カード上の向き UI（カードは背番号・名前・利き足のみ）
- **発見性は別件:** 三角が装飾に見える問題は、扇を足さずにヒント／how-to で扱う

旧 SPEC の「扇 = v1.1 Should」は本決定で上書き。ロードマップに戻さない。

### 決定ログ — ズーム時の駒サイズと Match Piece Size（2026-08-25）

**CK 等で画角を寄せたとき、駒はピッチと一緒に膨らませず、相対的に小さくして密度を解く。ただし Match の Piece Size（`pieceScale`）との整合を崩さない。**

いまの半径はフルピッチ矩形（ズームで画面上に伸びる方）基準なので、ズーム＝駒も同じ倍率で大きくなる。タクティカルには逆。狭い範囲（CK・ペナ）に両軍を詰めたいときに粒度が死ぬ。近年の CK 重要度とも合う。

**二層モデル（必須）:**

| 層 | 何か | UI |
|----|------|-----|
| **意図** | `pieceScale`（戦術大 / 標準 / 精密小・スライダー） | Match の Piece Size。ユーザが決める「この試合の駒の大きさ」 |
| **密度補正** | ズームに応じて半径を抑える（画面ほぼ一定、または `/ zoom^k`） | 自動。Match の数値を書き換えない |

- **整合:** フル画角で「戦術」なら大きく、「精密」なら小さい。寄せたあともその大小関係は保つ。補正は乗算のみ
- **やらない:** ズームで `pieceScale` をサイレント変更、CK プリセットだけ精密に飛ばす（ホイールと不整合）、Piece Size UI を隠してズーム任せにする
- **表示:** Match の `(1.00)` 等は常に保存値。画面上の見かけ半径とはズーム時に一致しなくてよい（意図の表示）

実装済（`densityZoom`：画面サイズはフル画角相当、`pieceScale` は乗算のみ）。

### 決定ログ — フォーメプリセット（2026-08-25）

**ZoneBoard は運営プリセットのフォーメーションを持たない。**

フォーメは試合・局面・監督で融通無碍で、カタログ化できない。Match の「フォーメ＋サブ配置」は「いまの名簿を保った並べ直し」に読めず、内部の 1–11 / 12–23 足場でピッチを差し替える破壊操作だったため **UI から非表示**。

- **残す:** 新規ボード／競技切替などの空を埋める内部足場（`formationPieces`）。商品名としては出さない
- **出さない:** 4-4-2 等の運営フォーメ一覧、Match 上の再適用ボタン
- **Later（有料 Local Library）:** ユーザが自分で保存した配置・局面・名簿セットの呼び出し。運営カタログではない。クラウド盤面 SaaS ではない（§6）

本線は **名簿 → チップで XI → ピッチ**。形はユーザが駒を動かす。

### 決定ログ — チーム表示（Home / Away / Both）と hideHalf（2026-08-25）

**よくある解説:** フルピッチでホームの形 → アウェイの形 → 両軍を重ねてシミュレーション。欲しいのは **所属チームの表示フィルタ**（駒は消さない）。

**タイミング:** 実況のインプレー中ではなく、**試合前・試合後（準備・振り返り）**。配信 chrome や Broadcast ワンタップ本線にはしない。

**置き場所（方針）:** **Scenes（準備で触る面）**。局面の「いま何を見せるか」。Match／ツールレール／配信端は不向き。

**制作会社で色が出る:** 局面3枚に分ける／1局面でフィルタ切替／半面だけ見せる等は会社・番組で違う。ZB はフィルタを **任意の準備ツール** として持ち、運用を強制しない。

**`hideHalf`（左右の空間）:** 機能として残してよい。セットプレーは画角ズーム推奨（SPEC）。**使い所の正本は薄い**——左右カットが番組文法の制作向けレガシー。チーム表示フィルタと役割を混ぜない（空間 ≠ 所属）。

- **やる（実装済）:** Scenes に Home / Away / Both。描画フィルタのみ（`teamFocus`）
- **やらない:** 配信 chrome の常設切替、実況ホットキー本線化、hideHalf をチーム表示の代わりにする

実装済（B-055）。

### 決定ログ — Pass ＝ ボール軌道（ラベル認知）（2026-08-25）

**設計:** `pass` 線種 ＝ ボールの移動（パス・クロス・シュート含む）。Select には描画を入れない。

**ユーザ認知:** 英語 Native の「Pass」は味方へのパスに狭く、CK クロス／シュート軌道までは読み取りにくい。コーチングアプリ経験者は Pass ツール＝ ball movement と分かる層もいるが、解説者向け ZB では **ヒントで ball path と明示**する（B-058 済）。

**Later:** `shot` 線種で Pass と意味分離（B-059）。TacticsBoard / FTB 追随。

### 決定ログ — Pen + Shift = 直線（2026-08-25）

**Pen 1本。Shift 押しながらドラッグ → 始点–終点の直線。** Figma 型。Bunseki 型の構造チェーン・チャネル境界に使う。第4線種・自動直線推測は作らない。Zone の Shift（正円）とは別ツールで衝突しない（B-060 済）。

### 決定ログ — 局面ごとの画角（2026-08-25）

**画角の正本は `scene.viewport`。** 局面＝配置＋描画＋カメラの再現パッケージ。CK 局面に切り替えると CK フレームに戻る。

- **無料:** 組み込みプリセット・局面記憶・Export current
- **Pro:** `viewportTemplates`（名前付き・試合横断）。UI は `FEATURE_PRO_VIEWPORT_TEMPLATES=false` まで非表示
- **`board.viewport`:** 移行用のみ（旧データを各局面へコピー）

### 決定ログ — 画角プリセットはキャプチャ再現単位（2026-08-25）

**プリセット画角はホイールのショートカットではなく、解説キャプチャの再現フレーム。**

CK 角の旧値はコーナー弧だけ入りゴールが外れ、サッカーライターが CK 戦術を語れなかった。毎回の微調整はプロダクト失敗。

- **原則:** ランドマーク必須セット → AABB → zoom/cx/cy（点ズーム禁止）
- **CK Must（動きの語彙）:** 角・ゴール・ペナ・ショート際・**レストDF（ハーフ付近）**。ゴール入りだけでは不足（教本・配信図）
- **外側:** ゴール裏・ピッチサイドは規定余白のみ（`CAPTURE_OUTSIDE_MARGIN`）。余りはピッチ内。毎回同じ余白＝ブランド再現
- **正本:** [`VIEWPORT_RESEARCH.md`](VIEWPORT_RESEARCH.md)。CK は `viewportCoveringRect`
- **参考:** [Professionalsoccercoaching](https://ja.professionalsoccercoaching.com/corners/soccercornerplays2) · [DiBernardo](https://coachdibernardo.com/2014/10/22/corner-kick-basics-attacking-defensive-corner-standard-set-up/) · [NYT](https://www.nytimes.com/interactive/2022/12/05/sports/world-cup/corner-kicks-world-cup.html)
### 決定ログ — ホーム／アウェイのデータ分割（2026-08-25）

**判断: 局面の配置は分けない。名簿は既に分けている。ライブ Scene を `homePieces` / `awayPieces` に割らない。**

| 層 | 持ち方 | 理由 |
|----|--------|------|
| **身分（名簿）** | `roster.home` / `roster.away`（既に別データセット） | 背番号・名前・キットはチーム所有。正しい |
| **局面の配置** | `scene.pieces[]`＋`team`（同一座標空間） | 「両軍シミュレーション」は相対位置・線・ボールが共面必須 |
| **見せ方** | `teamFocus`（ビュー） | データ分割ではなく投影 |

**分けたくなる動機（ホーム形→アウェイ形→重ね）は本物。** ただしそれは **編集セッション／表示の話** であり、永続モデルを二平面にすると次が壊れる。

- 両軍表示時のヒット・重なり・パス／プレス線（跨チーム）
- ボール1個・描画オブジェクト1レイヤの所有権
- Undo・選択・Export の「いまの局面」
- フィルタで隠した側への誤編集より、**マージ／同期バグの方が高い**

**Later（有料 Local Library と整合）:** チーム単位の **配置スナップショット**（ホーム形を保存して局面へ適用）は別データセットにしてよい。それは Scene のライブ状態の分割ではなく、テンプレ／ライブラリ。運営カタログではない。クラウド正本化ではない（§6）。

- **やる:** 身分はチーム別。局面は共面 `pieces[]`。表示は `teamFocus`
- **やらない:** `Scene.homePieces` / `awayPieces` へのスキーマ分割（いまのジョブのため）

### 決定ログ — 広告（2026-08-24）

**ピッチに広告は絶対に入れない。配信モード（Broadcast）にも入れない。**

配信キャプチャに乗る面（コート・駒・帯・ユーザーロゴ）へ、ZoneBoard 側の広告も、利用者が設定する広告枠も、一切出さない。LP や課金ページの広告・計測は別面。配信中のボードは広告面にしない。

## 6. 収益メモ

長時間セッション → Privnote型よりマシ。SUGUDASU本線とは別勘定。初期は無料+広告 or 後から Pro を検討可。

### 決定ログ — Pro = Local Library Entitlement（2026-08-27）

**クラウド盤面 SaaS を Pro の定義にしない。** Deep Research（競合境界・OBS 机・GDPR／運用コスト）と CTO/CMO/CPO 合議で確定。

> Pro は「クラウドの机」ではなく **「端末の引き出し」** を売る。  
> 描画・Broadcast・ロゴ・今夜の名簿貼り付けは無料のまま。アカウント必須にしない。

| 判定 | 内容 |
|------|------|
| **採用（Path 1）** | Local Library Pro — 名前付き選手セット、名前付き画角テンプレ、ボード／局面上限の緩和、JSON import/export |
| **棄却** | 盤面全体のクラウド正本化・ログイン必須を Pro の核にすること。**ZoneBoard 自前の Online Storage（預かりクラウド）** |
| **マルチデバイス** | **BYO Storage** — ユーザが既に持つ Drive / Dropbox / iCloud 等へ JSON を置く／開く。ZB は保管庫を運営しない |
| **Later** | Drive picker 等の深い統合。自前土管＋非送信認証（下記）。手運び JSON で足りない需要がインタビューで見えてから |
| **価格** | 未公開。一回買い（仮 $29–$39）または低額年額は仮説。配信者インタビュー後に決める。月額サブスクを本線にしない |
| **コピー** | Squad Presets / Matchday Viewports / JSON Export。使わない: Season roster management / Cloud sync（自社） / Drill templates |

**常に無料（楔）:** 自由描画・駒操作、Broadcast、ユーザーロゴ、単試合の手入力／貼り付け名簿。

**実装の足場:** [`src/lib/plan.ts`](../src/lib/plan.ts)（`activePlan` / entitlements）。Paywall UI・Merchant of Record は未着手。

**JSON backup:** ブラウザキャッシュ消失リスクへの逃げ道。export は楔として **無料でも出せる方向**を優先し、Pro は「複数ライブラリに取り込む／名前付きセットを保有する」側に寄せる（細部は実装時）。

#### Library 一覧 UI（2026-08-27）

Pro の「引き出し」には **一覧面が必要**（探す・改名・削除・適用・書き出し）。ただし第二ホーム／ダッシュボードにはしない。

| 判定 | 内容 |
|------|------|
| **置く場所** | Prep ドロワー内のタブ（または同等の準備面）「Library」 |
| **中身** | Squad Presets 一覧 + Matchday Viewports 一覧（適用＝このボード／この局面へ） |
| **やらない** | `/library` を第一画面にする、トップバー常設、クラウドの「最近のプロジェクト」ブラウザ |
| **空状態** | 「今夜の名簿からセットを保存」への導線。無料はセット無しでも今夜の試合は可 |

#### 同期・BYO Storage（2026-08-27）

> みんな既に Online Storage を持っている。ZB がもう一つ持つ必要はない。**参照する（指す）**。

| 段階 | 内容 |
|------|------|
| **今〜Pro v1** | 手動 JSON の書き出し／読み込み（BYO の最小形）。ノート↔配信 PC・共ホスト共有はファイル手渡し |
| **Later** | 「ユーザの Drive 等に保存／開く」（OAuth は **ストレージ提供者のログイン**であり、ZB ユーザ ID ではない、と文書で分離） |
| **本線にしない** | スマホでライブ駒操作を前提にした三画面リアルタイム同期（watchalong 本線は固定 PC + OBS） |

PC / Tablet / SP の「汎用」は **同じファイル形式が開けること**で達成する。ZB 同期サーバで達成しない。

#### 認証・ユーザ ID・1Password 式（2026-08-27）

参照: [SUGUDASU「非送信」× Sync（Zenn）](https://zenn.dev/sugudasu/articles/abe874966cf373) — 憲法は SUGUDASU と揃えてよい。

| レイヤ | 方針 |
|--------|------|
| **Pro（Local Library）** | ログイン不要。ユーザ ID を持つ場面を作らない |
| **課金証明** | ライセンスキー等（MoR）。メール名簿型の自前アカウントは採らない |
| **自前 Sync 土管が要る場合（Later・非本線）** | 通常の「メール＋パスワードをサーバへ」は採らない。Secret Key + パスワード非送出（1Password / SRP 系）を検討。サーバは ciphertext の土管 |
| **ZB での優先** | BYO で足りる間は自前 Sync を作らない。SUGUDASU Sync と設計を共有できる予約席に留める |

#### VC・マネタイズの見せ方（2026-08-27）

ストレージ課金・預かりクラウドの単位経済には振り切らない。物語は次の三段:

```
Free wedge     描画 / Broadcast / ロゴ     → 成長・口コミ
Pro (ARPU)     Local Library               → 本命の収益（準備時間の削減）
Portability    BYO file（ユーザの保管庫）   → 預からない・マルチデバイス
```

Gross margin は静的配信 + MoR 前提で高く語れる。転換率・価格はインタビュー前は仮説のまま。

### 無料 / Pro（方針・未実装）

| | **無料** | **Pro** |
|--|----------|---------|
| コア（配信・描画・ロゴ・ズーム） | 全部使える | 同じ（楔は削らない） |
| 試合ボード / 局面 | 上限あり（3 / 8） | 緩和（`PLAN_LIMITS.pro`） |
| **選手セット** | いまの試合ボードに紐づく名簿のみ | **名前付きセットを複数保有（ローカル）** |
| **画角** | 組み込みプリセット・**局面ごとの記憶**（`scene.viewport`）・Export＝いまの画角 | **名前付き画角テンプレ**（試合をまたぐローカルライブラリ） |
| **持ち運び** | JSON export（逃げ道・共有・BYO の種） | import → ライブラリ反映、上限緩和。保管庫はユーザ側（BYO） |

**画角の無料 / Pro 切り分け（2026-08-25）:**

| | **無料** | **Pro** |
|--|----------|---------|
| CK 等の組み込みプリセット | ○ | 同じ |
| 局面切替で画角が復元（`scene.viewport`） | ○ | 同じ |
| Export「いまのズーム」＝画面と一致 | ○ | 同じ |
| 「うちの番組用」名前付き画角 | — | **複数保存・横断呼び出し（ローカル）** |

組み込みフレームと局面記憶は **キャプチャ再現の楔**。カスタムテンプレは名簿セットと同じ **横断ライブラリ** が Pro 核。実装: `viewportTemplates` + `FEATURE_PRO_VIEWPORT_TEMPLATES`（`hasEntitlement("viewportTemplates")`）。

**選手セット（Pro の核）— 役割分担:**

| 誰がやる | 何を |
|----------|------|
| **プロダクト** | カラム（スキーマ）を先に固定。空欄可。無料の試合名簿も同じ形 |
| **ユーザ** | 中身の作成（貼り付け・手入力・ボードから「セットとして保存」） |
| **公式データ** | ライブ取込・スクレイピングは **しない**。必要なら静的な参考テンプレ（番号枠だけ、コピペしやすい表）程度 |

| カラム | 必須 | 備考 |
|--------|------|------|
| `number` | **必須** | 識別子 |
| `label` | 任意 | 名前 |
| `preferredFoot` | 任意 | `L` / `R` / `B` |
| `defaultColor` | 任意 | セット単位のチーム色 |

セットの CRUD は Pro 実装時（**ローカル entitlement** + Prep 内 Library 一覧。ZB 預かりクラウドはしない）。v1 はボード紐づき名簿のみ（カラムは既に同じ）。

地方大会は番号だけ、代表戦は番号＋名前＋利き足、をセットごと保存して呼び出せる。駒カードは **トリプルクリック / 右クリックで欲しいときだけ**（単クリックは移動のみ。ダブルクリックは使わない）。カード項目は **背番号・名前・利き足** のみ（国籍・成績・プレースタイル文は載せない）。向き UI・視野角扇は出さない（決定ログ 2026-08-25）。

**価格決定前のインタビュー（EN watchalong）:**

1. 名簿は何日前に／キックオフ何分前に、どのマシンで入れるか  
2. 一回買い（例 $35・ローカルライブラリ）と月額同期アカウントのどちらが欲しいか  
3. 共ホスト／編集者へのボード共有を今どうしているか  

**Later — コミュニティ内のデータ流通:**

カラムが固定されていれば、セットはファイル／リンクでやり取りできる。解説者同士・部活同士で「今季の背番号表」を共有するマーケットがコミュニティ内に自然にできるとよい。運営が選手 DB を売るのではなく、**ユーザが作ったセットの流通**。権利・正確性は投稿者責任。Pro の「複数セット保有」がその前提になる。

**流通の場所（自ドメイン下には置かない）:**

| やること | やらないこと |
|----------|--------------|
| エクスポート形式を公開し、FAQ に「共有のしかた」を書く | `zoneboard.app` 上の公式マーケット／フォーラム |
| 既存コミュニティへの**軽い種まき**（スレッド・ピン留め例） | 運営が FanCommunity をホスト・モデレートする |
| 完全な自然発生だけに賭ける（フォーマットが知られない） | Reddit だけを公式コミュニティにする（日本人には敷居が高い） |

種まきの置き場は「すでに人がいる場所」に寄せる。

- **日本語:** X（解説・部活の既存タイムライン）、Discord（配信者サーバ）、note など。必要なら FAQ から「共有タグ例」を示す程度
- **英語:** Reddit スレッドは可（EN 向け）。JP の主戦場にはしない

FanCommunity はプロダクト機能ではなく、**フォーマットが揃った結果として外で起きるもの**。運営の仕事はスキーマと import/export と FAQ まで。
