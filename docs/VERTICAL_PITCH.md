## 1. ジョブ

紙の戦術書・縦配信・スマホ／SNS 向けに、**ゴールが上下の真上作戦盤**を最初から組める。

横ボード（OBS 既定）は残す。縦は **別ボード（別データ）**。

---

## 2. 一言で何か

現行 ZB のピッチ描画を **90°した世界**で新規に置く。  
受け入れ絵: 現行キャプチャをペイントで 90°し、駒オブジェクトを置いただけ。

---

## 3. データモデル

| 項目 | 仕様 |
|------|------|
| **置き場** | `BoardDocument`（試合単位）。局面スイッチで向きが変わらない |
| **提案フィールド** | `pitchOrientation: "landscape" \| "portrait"`（名前は実装時に合わせる）。既定 `"landscape"` |
| **新規** | 縦で作ったボードは最初から `portrait` |
| **座標** | そのボードのピッチ矩形 `(x,y)` 0–1。縦用に新規配置する。**横局面からの写像はしない** |
| **論理比** | 横: 既存 `SPORT_RATIO`（サッカー 105:68）。縦: **比を入れ替え**（サッカー 68:105）。ハーフは既存と同じ「長さの半分」を縦世界で適用 |
| **既存** | `pitchView` `full` \| `half`、`pitchFlipped`、`showLanes5` はそのまま使う |

**軸（縦ボード）:**

- 画面 **上下** ＝ ゴール↔ゴール（長さ）
- 画面 **左右** ＝ タッチライン↔タッチライン（幅）
- 5レーンは **ゴール方向に走る**（ペイントモックどおり縦の破線）

正規化 0–1 は **その向きのピッチ矩形**に対して。横ボードの 0–1 とは別空間。

## 4. やる / やらない

### やる

| # | 内容 |
|---|------|
| 1 | 縦フルピッチ（サッカー最小）。芝・線・レーン・外周緑は現行と同じ図法を 90°した見た目 |
| 2 | 縦のまま **フル ↔ ハーフ**（ハーフにしたい人はいる） |
| 3 | ハーフの **反転**（既存 `pitchFlipped` 相当。縦では「上下どちらが攻撃側か」） |
| 4 | 駒・ボール・Pen・**Run / Dribble / Pass / Link** は既存ツールのまま。楔は構造線＋駒 |
| 5 | 背番号・ラベルは **画面正立** |
| 6 | 駒は芝上および **サイド余白（outer）** に置ける（モックどおり） |
| 7 | Export: 既存の投稿用縦比（9:16 / 4:5 等）と接続。縦ボードは contain で焼く |

### やらない

| やらない | 理由 |
|----------|------|
| 同一局面の **横 ↔ 縦** 切替（座標持ち越し） | 必要性が薄い。レイアウト以上の難度 |
| 縦用に **試合展開の帯を再設計** | 16:9 では余白が出る。帯は横ボードの仕事 |
| 16:9 余白を ZB が埋める | **Streamer／Vtuber・コメント**は OBS 側 |
| 実写下地・Homography | **B-070**（次期大型）。本仕様の外 |
| 駒なし赤入れ（矢印だけ） | [SUGUDASU 赤入れ](https://sugudasu.com/annotate) の席 |

## 5. レイアウト・OBS

| 層 | 仕様 |
|----|------|
| **既定ボード** | 横のまま。既存配信を壊さない |
| **縦ボード** | 最初から縦。配信中に横ボードを縦にしない（比の跳ねはユーザが縦ボードを選んだときだけ） |
| **16:9 モニター** | 縦ピッチは中央 contain。左右ピラーが出てよい |
| **試合帯** | 縦では **敢えて出さない**（`showMatchBanner` オフ固定、または縦では描画しない）。縦用帯 UI は作らない |
| **配信マット** | 既存 `BROADCAST_MATTE`。ピラーは顔・コメント用の「空き」 |

編集キャンバスがウィンドウいっぱいに伸びる場合も、ピッチ自体は縦比を保つ（歪めない）。

## 6. UI

| 項目 | 仕様 |
|------|------|
| **ピッチ見た目（方針更新 · 2026-08-31）** | [The Tactics App](https://thetacticsapp.com/) の **Pitch View** 型を採る（まるっと真似てよい）。試合タブの **向きセグメント＋フル／ハーフサムネ＋反転** をやめ、**線画アイコンの1セグメント**に統合する |
| **一意（必須）** | **アイコンの絵 ＝ 今の向き・フル／ハーフ。** 押したアイコンとキャンバスが一致しない状態を作らない。予約向きだけ青くて下の絵は横、は禁止 |
| **アイコン案（5）** | ①横フル ②縦フル ③縦ハーフ（ゴール下） ④横ハーフ ⑤縦ハーフ（ゴール上）。選択＝その見た目。サムネが嘘をつかない |
| **レーン** | ピッチアイコンに描かない。既存どおり文字セグメント（なし／レーン） |
| **ツールレール** | 向きで並べ替え・アイコン化しない（言葉のまま） |
| **横↔縦を押したとき（データ）** | **実装済（Pitch View UI）:** 向きが変わるプリセット → 全局面リセット（駒空・中央ボール）。同向き内フル↔ハーフは保持。[`AGENT_PROMPT_PITCH_VIEW_UI.md`](AGENT_PROMPT_PITCH_VIEW_UI.md) · `src/presets/pitchLook.ts` |
| **やらない（UI）** | 「次の新規用」向きだけが青く、下のピッチ絵は横のまま、という二重時計 |
| **i18n** | グループに `pitchView` 相当ラベル。各アイコンは `title` / `aria-label`。ドロワー幅を広げない。線画は ~40px 級で5つが1行に収まること。`npm run test:i18n-chrome` |
| **画角プリセット** | 縦ボードでは **別実装**（カメラ座標の軸が変わる）。横は既存 `VIEW_PRESETS` のまま。[`AGENT_PROMPT_PORTRAIT_VIEWPORT.md`](AGENT_PROMPT_PORTRAIT_VIEWPORT.md) |

**参考:** Pitch View の見た目・並びは The Tactics App のセグメント（線画・区切り・青枠選択）を正とする。コーチ／教材寄りプロダクトだが、**ピッチの切り方の認知**は配信でも同じ。

## 8. 実装メモ（現行コードとの接点）

事実（捏造しない）:

- 論理比は `aspectFor`（`src/presets/sports.ts`）。いまは常に横長
- フィットは `fitField`（`src/canvas/layout.ts`）。`oh = ow / aspect`
- 芝・線は `drawPitch*`。ゴール↔ゴール＝横軸前提
- 配信フレームは `BROADCAST_FRAME_ASPECT = 16/9`

**本丸:** 枠の CSS 縦長だけでは足りない。**描画をゴール上下にする**（軸入替、または現行描画の 90°世界＋入力をその世界に合わせる）。駒座標は縦ボード内の 0–1 のみ。

見積（参考）: サッカーフルのスパイク 0.5〜1日。編集・Export・OBS で使える縦ボード 2〜4日。全競技は後。

## 9. 受け入れ条件

次が揃えば最小スコープ達成。

1. 新規縦ボードで、ゴールが上下のフルピッチが見える（現行図法の 90°）
2. レーンがゴール方向に走る
3. 駒を芝とサイド余白に置ける。番号は正立
4. Run / Dribble / Pass が引ける
5. 試合帯が出ない（または出さない）
6. 横ボードの局面が縦に変換されない
7. 縦のままフル／ハーフが切替できる（ハーフは最小の直後で可。フルだけのスパイク可）
8. 既存横ボードの OBS 比が、縦ボードを触らない限り変わらない
