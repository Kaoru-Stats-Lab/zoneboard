# Broadcast — 交代 / 負傷の表示研究

**更新:** 2026-08-26  
**優先:** PH 日程より **Broadcast 必須**  
**問い:** 交代枠が増えた現在、TV / Online はどう見せているか。ZoneBoard の配信キャプチャで **CL でも通用する**見せ方は何か。  
**キャンバス:** `broadcast-subs-display.canvas.tsx`（Cursor）

---

## 0. ルール側の前提（表示を圧迫する理由）

| 項目 | いまの主流（CL / 五大 / FIFA 系） |
|---|---|
| **使える交代** | 多くが **5**（延長 +1 など大会差あり） |
| **ウィンドウ** | 多くが **3 回**（ハーフタイムは別カウント） |
| **脳震盪** | 追加の恒久交代 + 相手にも同数（PL の緑カード等） |
| **名前付きベンチ** | 大会で 9〜12 など。**使った数 ≠ ベンチ人数** |

3 交代時代の「下段に OUT/IN を1行」でも足りた。**5＋ウィンドウ＋脳震盪**になると、「いま何人使ったか」「次は窓が残っているか」が視聴者の問いになる。

ZoneBoard は **試合映像の scorebug ではない**（顔・時計は OBS）。ここでは **戦術ボード上で XI の状態が読めること**が CL 水準の定義。

## 1. TV / Online の表示パターン（MECE）

調査ソース: FIFA WC グラフィック解説（SVG Europe）、Amazon PL scorebug（Independent 2023）、PL concussion 運用（Sky）、UEFA 第4審判ボード（Hublot）、DAZN/Servus CL Vizrt パッケージ、FIFA 交代史。

| ID | どこ | 何を見せる | 強み | 弱み · ZB への適合 |
|---|---|---|---|---|
| **A. 第4審判ボード** | ピッチサイド実物（Hublot 等） | ON/OFF 番号・追加時間 | カメラが映せば一次情報 | 配信者のボード製品ではない。ロゴ板の模倣は禁止領域 |
| **B. イベントチップ / ロワーサード** | 試合映像オーバーレイ | `↓OUT ↑IN`・分・チーム色。WC は **残り交代数**も同アニメに載せる | 瞬間の物語が clearest | 面積を食う。ZB が常時出すとピッチ ≥80% 契約を壊す |
| **C. Scorebug メーター** | 常時スコア帯（Amazon PL の白ダッシュ等） | チーム略称上に **残り5→減る** | 5交代時代の「残弾」が一目 | Sky 等は非標準。OBS 側スコアと二重。ZB の本業外 |
| **D. XI / フォーメーション板** | 解説用フルスクリーン or ワイプ | 出場中・交代済に取り消し線 | 戦術説明向き | 瞬間のライブ向きではない。ZB の局面に近い |
| **E. ティッカー / アプリ** | 配信横・スマホ | 時系列リスト | 履歴が完全 | キャプチャ内に長リストは不可 |
| **F. 負傷プロトコル** | 実況＋担架＋（脳震盪）緑カード | 「普通の交代ではない」 | 安全シグナル | TV でも scorebug 常時マークは弱い。ZB では **駒の見た目差**が本命 |

**結論（業界）:**  
- **瞬間**は B（チップ）。  
- **残弾の常時**は C（一部配信のみ — ZB では**採用しない**）。  
- **戦術理解**は D。  
- **ZB が盗むべきは D の状態表現 + B の瞬間の短さ**。枠レギュレーションは Streamer が知らなくてよい → 残数 UI は作らない。

## 3. CL 水準の定義（ZB 用）

CL の Vizrt パッケージをコピーすることではない。次を満たすこと:

1. **1080p ウィンドウキャプチャで、背番号の IN/OUT が1秒で読める**  
2. **5–5 交代後も芝がゴミにならない**（履歴は畳む）  
3. **負傷 ≠ 戦術交代**が色や記号で区別できる  
4. **OBS の cam/chat/score と役割が被らない**（常時巨大ロワーサードを出さない）  
5. **番号が先、名前は任意**（製品の楔を守る）

## 4. 推奨アーキテクチャ（3層）— **決定済 2026-08-26**

### 決定（カオル）

| 項目 | 決定 |
|---|---|
| OUT の置き場 | **ベンチ帯内 + 記号**（別レールは作らない） |
| 残数 / 枠上限 | **作らない**（大会差・Streamer が知らなくてよい。汎用の OUT/IN/INJ のみ） |
| 駒の移動 | **状態と座標は独立。OUT / IN / INJ でも芝に置いて動かしてよい** |

**なぜ OUT しても芝に戻すか:** 解説は「いまの XI」だけではない。「ここを守っていた 5 番が降りたあと、この空間が空く」を示すために、**降りた駒を図の上で語る**のが普通。状態マークは残しつつ、ドラッグは自由。位置で `role`（starter/bench）を縛る現行ロジックとは別に、**match status（on/out/injured）** を持つ。

### L1 — ピッチ上の状態（常時 · 最優先）

| 状態 | 見せ方 | 移動 |
|---|---|---|
| **on（出場中）** | 現行スターター | 自由 |
| **in（途中出場）** | 通常サイズ。短い IN 印は任意・消せるとよい | **自由**（自在） |
| **out（交代で降りた）** | 既定はベンチ帯＋ **OUT 記号**。芝に戻しても OUT 記号は残る | **自由**（解説用） |
| **injured** | OUT と同型だが **INJ 記号**（斜線等。赤カードとは別） | **自由**（原則ベンチへ送る操作はあるが、ロックしない） |
| **unused bench** | 現行ベンチ | 自由 |

「いまの実 XI」を読みたいときは: **on/in のみを見る**（out/injured は記号で除外）。解説モードでは out 駒を芝に置いてよい。

### L2 — Broadcast イベントチップ（瞬間）

得点・カードと同列:

```
SUB  67'  H  9↓ 14↑     [INJ]
```

- 必須: 分 · チーム · OUT 番号 · IN 番号  
- 任意: INJ  
- 1.5–2.5 秒強調 → L1 の状態が残る  
- 名前は出さない  

### L2b — 残数 → **作らない（決定 2026-08-26）**

Streamer は交代枠レギュレーションを知らない。枠は大会・延長で変わる。  
**残数メーター（H 2/5）は出さない。** `maxSubs` は互換のためデータに残すが UI・製品ロジックに使わない。  
交代は OUT/IN/INJ の状態と SUB 行だけで、枠を知らなくても Broadcast できる。

### L3 — 履歴（畳む）

- 自動タイムラインは後  
- キャプチャ内ティッカーは出さない

## 5. やらないこと

| 禁止 | 理由 |
|---|---|
| Hublot / 大会公式ボードの複製 | ブランド・用途が違う |
| 常時ロワーサードで芝を 20% 以上隠す | OBS 契約·SPEC |
| 5人分の名前プレートを同時表示 | 番号製品·可読性 |
| OUT 駒を芝に置けなくする | 解説の「かつてここにいた」が死ぬ |
| **残数 / 枠上限 UI** | 規制依存。Streamer が知らなくてよい |
| ウィンドウ残りを v1 必須にする | 大会差・誤表示リスク |
| 脳震盪緑カードの完全シミュ | 医療プロトコル。INJ 記号で十分 |

## 7. 決定ログ

1. OUT → **帯内記号**  
2. 残数 → **作らない**（枠は汎用・知らなくてよい）  
3. IN/OUT/INJ → **駒として自在**  
4. PK → **○✕ 結果列**（キッカーは直前入力）。詳細は BROADCAST_PK.md  

---

## 8. 次の論点 — 延長は「枠」を増やさない

延長で交代が増えても **残数を出さない**方針は同じ。必要なら「あと何回」ではなく、いままで通り OUT/IN を足すだけ。

PK は別ドキュメント。
